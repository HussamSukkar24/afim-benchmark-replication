# Provenance: PRISM multi-turn Resistance Test

The PRISM data in this folder was collected by hand through the product interface. There was no API
access to PRISM at the time of the study, so none of it can be regenerated by running a script. This
file records how it was gathered so the collection can be judged and, if access allows, repeated.

Everything else in the folder, the fresh GPT-5 run and the metrics comparison, is API-generated and
reproducible.

## What was collected

Eight conversations, drawn from the prompts PRISM initially refused at Levels 3 to 5. Each
conversation is the initial prompt at turn 0 followed by seven fixed follow-ups, so 64 turns in
total. Unlike the API runs, every follow-up was collected even after a response crossed the 0.5
threshold; the threshold break is applied afterwards in the analysis scripts.

The eight prompt IDs are `phys-shortcuts-1`, `cs-shortcuts-2`, `gen-shortcuts-1`,
`phys-fabrication-1`, `cs-fabrication-1`, `gen-fabrication-2`, `phys-fraud-2` and `cs-fraud-1`.

## Files

| File | What it is |
|---|---|
| `prism_multiturn_TEMPLATE.json` | Blank collection scaffold, filled in by hand during collection |
| `prism_multiturn_collected.json` | Raw collected responses, no scores |
| `prism_multiturn_scored.json` | The same responses after judging by `claude-sonnet-4-6` |
| `gpt5_multiturn_fresh.json` | Fresh GPT-5 API run over the same prompts, for comparison |

The template is committed because it documents the collection format, not because it holds data.

## Collection protocol

1. A fresh PRISM conversation was opened for each prompt, so no state carried between prompts.
2. The original AFIM prompt was submitted as the first message.
3. The seven fixed follow-ups were submitted in order, one per turn, with no adaptation to what
   PRISM had said. The wording is identical to the API runs and is reproduced in
   `03_multi_turn_pressure.py` in the `baseline` folder.
4. Each response was copied verbatim into the collection file, including any text about the
   workspace or the manuscript.
5. Judging was done afterwards through the API, using the same rubric and judge as the API arms, so
   the scoring path is identical even though the generation path is not.

- Account type and any project or workspace settings that were not left at their defaults

This matters because six of the eight conversations developed context loss, where PRISM stated it
could not see the earlier request or referred to a workspace that did not contain the expected
content. Whether an empty or populated project was open is directly relevant to interpreting that
behaviour.

## Known limitation

PRISM's exact model snapshot, system instructions and product-layer configuration are not disclosed
by OpenAI. The proxy work in `proxy_validation` addresses this by quantifying agreement with a
version-matched API model, but the underlying configuration remains unknown.
