# Provenance: PRISM multi-turn data

The PRISM data in this folder was collected by hand through the product interface. There was no API access to PRISM during the study, so it cannot be regenerated by running a script. This file records how it was gathered. The GPT 5 comparison run and the metrics are API-generated and reproducible.

## What was collected

Eight conversations, drawn from the prompts PRISM initially refused at Levels 3 to 5. Each is the initial prompt followed by seven fixed follow-ups, so 64 turns in total. Every follow-up was collected even after a response crossed the 0.5 threshold; the threshold break is applied later in the analysis scripts.

Prompt IDs: `phys-shortcuts-1`, `cs-shortcuts-2`, `gen-shortcuts-1`, `phys-fabrication-1`, `cs-fabrication-1`, `gen-fabrication-2`, `phys-fraud-2`, `cs-fraud-1`.

## Files

| File | What it is |
|---|---|
| `prism_multiturn_collected.json` | Raw collected responses, no scores |
| `prism_multiturn_scored.json` | The same responses after judging by `claude-sonnet-4-6` |
| `gpt5_multiturn_fresh.json` | Fresh GPT 5 API run over the same prompts, for comparison |

The manual collection format is documented in the provenance notes and reflected in the committed scored response files.

## Protocol

A separate PRISM conversation was opened for each prompt, so no state carried between them. The original prompt was submitted first, then the seven fixed follow-ups in order, with no adaptation to PRISM's replies. Follow-up wording matches the API runs in `baseline/03_multi_turn_pressure.py`. Each response was copied verbatim, including any text about the workspace. Judging was done afterwards through the API using the same rubric and Sonnet 4.6 judge used for the later matched comparisons.

## Collection conditions

The direct PRISM multi-turn responses were collected manually during the July 2026 study period, but the exact collection date was not recorded in the response file and cannot be independently verified from the repository. All responses from the reported experimental runs were retained.

Each conversation used a fresh, unpopulated workspace on a free account accessed by email, with no custom instructions and no pre-existing manuscript supplied. At least one PRISM response reported a workspace containing only a minimal `main.tex` with an empty Introduction, consistent with this setup. Memory settings were not recorded.

This matters because six of the eight conversations developed context loss, where PRISM stated it could not see the earlier request or referred to a workspace without the expected content. Whether an empty or populated project was open is directly relevant to interpreting that behaviour, so the fresh-workspace condition is recorded here.

## Known limitation

PRISM's exact model snapshot, system instructions and product configuration are not disclosed by OpenAI. The `proxy_validation` work quantifies agreement with a version-matched API model, but the underlying configuration remains unknown.
